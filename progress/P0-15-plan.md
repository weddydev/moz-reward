## Design requirements from the security check (HIGH = must be in the first version)
- **HIGH release secrets:** the owner URL and every secret reach containers via **stdin** over the SSH session (`docker run --rm -i … node cli/migrate.mjs` reading the URL from stdin; helper reads secrets from stdin) — never `-e`, `--env-file`, argv or a host file for the owner URL.
- **HIGH Caddy logs:** `log { format filter }` drops the query string, `Cookie`, `Authorization`, `Proxy-Authorization`, `Set-Cookie`; the System-page aggregator keeps route template, status, duration only.
- **HIGH Redis:** password + TLS + key prefix on **both** redis-queue and redis-cache (boot requires it): per-env internal CA generated on the host by the root helper (keys root-only, mounted read-only), `port 0` + `tls-port`, ACL user per client (not `default`), `internal: true` network.
- **HIGH Postgres bootstrap:** `REVOKE ALL ON DATABASE <app>,<umami> FROM PUBLIC` then CONNECT per role; `ALTER SCHEMA public OWNER TO moz_owner`; `REVOKE CREATE ON SCHEMA public FROM PUBLIC`; superuser `CREATE EXTENSION postgis` then re-apply 0010's `spatial_ref_sys` revokes; scram-sha-256 (pg_hba + `password_encryption`); `moz_owner` NOSUPERUSER NOBYPASSRLS **NOCREATEROLE** (bootstrap pre-creates the 4 roles, grants moz_rls WITH ADMIN). Test with `has_database_privilege` / `has_table_privilege`.
- **HIGH sshd:** drop-in `00-moz.conf` (cloud-init's `50-cloud-init.conf` sets PasswordAuthentication yes and first value wins) or remove it; KbdInteractive no, PermitRootLogin no, AllowUsers, MaxAuthTries 3, forwarding off; `sshd -t` before reload, assert with `sshd -T`; ufw allows 22 **before** enable.
- **HIGH Umami:** dashboard host behind Cloudflare Access; human changes default admin password; exact-path matchers for `/u/script.js` + `/u/api/send`, 404 the rest of `/u/`; strip `Cookie`/`Authorization` up and `Set-Cookie` down.
- **HIGH deploy user:** NOT in the docker group. CI key: `restrict,command="sudo /usr/local/sbin/moz-deploy"`; sudoers allows only that path; helper root-owned, validates `SSH_ORIGINAL_COMMAND` (allowlist `load|release|rollback|write-env`, env ∈ staging/production, 40-hex SHA), runs under `env -i`, secrets on stdin, checks loaded image tag = SHA. Developers get their own sudo users, not the forced-command key.
- MEDIUM: committed `known_hosts` + `StrictHostKeyChecking yes` in CI (no keyscan). B2: one key per env with `namePrefix`, write+list only (read only if wal-g needs it), lifecycle hide 35 d → delete (or Object Lock governance); separate keys for `wal-g delete` and `backup:verify` (human tasks). Dumps: `docker exec -u postgres pg_dump -Fc` over the socket → `gpg --recipient <full fingerprint>` with own GNUPGHOME; plaintext only on drill night (0700 dir, `trap` delete); drill restores into `--network none` container; heartbeat writer role limited to `job_heartbeats`. WAL: Postgres on internal net + separate egress net; alert from `pg_stat_archiver` within 10 min; RUNBOOK lever to no-op `archive_command`. Caddy: exact hosts, default 404, `header_up X-Forwarded-Host {host}`, `TRUSTED_PROXY=cloudflare` semantics checked, `header_up -Authorization` on staging, `admin off`, `auto_https off`, `-Server`, `request_header X-Request-Id {http.request.uuid}` (C-23). Role passwords generated on the host / piped to `gh secret set`, never printed, `log_statement=none` explicit. Prod deploy: re-run Trivy + slim check + boot smoke on the prod-args image; tag commit ancestor of main with green push CI; `inputs.tag` via `env:`; per-env `concurrency`. Compose: `read_only` + tmpfs (web `/app/.next/cache` uid 1000), `cap_drop: ALL`, `no-new-privileges`, `pids_limit`, `init`, `restart: unless-stopped`, **no `ports:`** (CI lint); worker overrides the image HEALTHCHECK; daemon.json `live-restore`, `no-new-privileges`, `userland-proxy: false`, log size documented in RESOURCES. `backup:verify`: DPIA/ROPA note, encrypted disk, deletes scratch DB + GNUPGHOME; the human runs it, Claude sees pass/fail only.
- LOW: Docker apt origin in unattended-upgrades + explicit reboot time; fail2ban `backend = systemd`; `ufw limit 22` + IPv6; cloudflared `--no-autoupdate` + ingress catch-all 404; ZAP artifacts short retention; DECISIONS: GitHub Free repo secrets readable by any branch's workflow, never `pull_request_target`. Image job: run the container and curl `/api/health/ready` (needs a DB service); esbuild metafile → `cli/.bundled/<pkg>/package.json` so Trivy/SBOM see bundled packages.

## D design check (security-reviewer, 13 Nov, Mac) — requirements for D1–D4
- **HIGH 1 history:** B2 Object Lock on the bucket, governance mode, default retention 35 d production / 7 d staging; host keys without `bypassGovernance`/`deleteFiles`; per-prefix lifecycle rules replace "keep only the last version" (H-42). D4 proves an overwrite leaves the locked version.
- **HIGH 2 WAL never in clear:** wrapper and `backup-push` exit non-zero unless the key file exists and its fingerprint equals the **host-pinned** one; moz-deploy builds the wal-g settings itself from an allowlist (only key id + secret come from CI; endpoint, bucket, prefix, PGP path fixed); test: every uploaded WAL/base object starts with an OpenPGP packet.
- **HIGH 3 lever:** archive-off file on a root-owned read-only mount (not PGDATA); `health.backup` alerts while it exists; RUNBOOK: removing it is followed at once by `backup-push`; `wal-g` under `timeout` (a hang = failure).
- **HIGH 4 base backup:** heartbeat `backup:base` on success; alert when > 8 days.
- **HIGH 5 dump:** `pg_dump | gpg > file`, check `PIPESTATUS`; heartbeat only after HTTP 200 + checks; any failure writes `backup:dump-failed` → immediate alert (like drill-failed).
- MEDIUM: fingerprint pinned on the host by `init-env` (root-only), not taken from the release; alert 30 d before key expiry (key has none today). B2 secrets not in the Postgres container env: file 0440 root:999 sourced by the wrapper. Drill: delete leftover plaintext at start; unit `UMask=0077`, `PrivateTmp`, `ProtectSystem=strict`; scratch container `--memory/--cpus`, `--read-only`, `--cap-drop ALL`, trust auth only with `--network none`; bootstrap.sql roles first, then `pg_restore --exit-on-error`; checks.sql also checks grants (`has_table_privilege`); prefer `tee` into pg_restore (no plaintext on disk). No read capability: prove with a MinIO policy of PutObject + ListBucket only, then D4 with the real key; set explicitly `WALG_DELTA_MAX_STEPS=0`, `WALG_PREVENT_WAL_OVERWRITE=false`, `WALG_COMPRESSION_METHOD=zstd`, path style, region, upload concurrency. ETag check: strip quotes, fail on multipart `-N`; save the PUT version id and check via ListObjectVersions it is the only version; only backup:verify proves decryptability → after launch monthly backup:verify (human task). Storage: estimate 35 d prod + 7 d staging WAL (≤ 1,440 segments/day/env) vs 10 GB in RESOURCES; budget B2 Class C calls (2,500/day free, $0 caps); lifecycle cancels unfinished large files after 1 d. GDPR: B2 in processor register/ROPA + DPA with UK addendum before production data (C-41/H-23), COMPLIANCE processor table still says R2; total retention ≤ 35 d (hide 34, delete 35); RUNBOOK restore re-applies erasures made after the restore point from a log that survives the restore.
- LOW: heartbeat via SECURITY DEFINER `record_backup_heartbeat(name)` accepting only `backup:%` (instead of table grants); DOCKER-USER rule: `pg_egress` outbound 443 only; gpg `--compress-algo none`; curl `--proto =https --fail-with-body`; timers `Persistent=true`; null `pg_stat_archiver` = failing (tested); `flock` shared by backups and deploys (02:30 dump vs migration `lock_timeout`).
