## 2026-11-11 — P0-09 design review fixes: table column widths, KPI line breaks, "Device" label
Decision: `Column.width` (optional CSS length) switches a Table to `table-layout: fixed` with a `<colgroup>`, so columns don't move between loading, empty and full; the empty message is pinned to the region's visible width (`@container` + `100cqw`, sticky). KpiCard values may wrap only after a thousands separator (`<wbr>` + `word-break: keep-all`), never inside a digit group. The motion preference's first option is now "Device" (was "Device setting", which wrapped in its pill at 320/390); SegmentedControl labels stay on one line (ellipsis on the label span, not the button, so `hit-44` isn't clipped).
Why: design-reviewer MEDIUM findings (empty row clipped, "£1,234,56 / 7.89", wrapped segment, 70px column shift loading → data).
Consequence: P1/P2 tables should give every column a `width`. Copy elsewhere (Me tab, P1) uses "Device" for "follow the device setting".

## 2026-11-11 — Gallery state matrix, long button labels, table row height, toast pause (P0-09 step D)
Decision: `/dev/ui` gives every primitive its own `Demo` block (`data-primitive`, name typed against `src/features/dev/gallery-list.ts`); prop states (disabled, loading, error, selected, empty, edge values) are shown side by side, while hover, focus-visible and pressed stay live, not faked with forced classes. A long Button label wraps (centred) and the button grows from a minimum height (`min-h-*`, was fixed `h-*` + `nowrap`); it is never truncated. Table data and skeleton rows share one minimum height (`h-12` / compact `h-9`). Toast hover and focus pause independently.
Why: forced-state classes would ship gallery-only CSS to every page. DESIGN is silent on long labels, and wrapping keeps the visible text equal to the accessible name. Mixed inline content (row button, mono span) made data rows 2px taller than skeleton rows (AC 9). On touch screens every tap ends with `pointerleave`, which restarted a toast's timer while focus was inside it.
Consequence: hover, focus and press are proven by E2E (AC 4, 5, 7; P0-08 focus crops), not by screenshots. In WebKit, `/dev` content streamed behind the `connection()` gate stays hidden until the JS loads (Chromium reveals it earlier); C-20 counts "hidden" as safe. Customer pages that stream the same way get the same check on Safari when they are built.

## 2026-11-11 — Overlays on the native modal `<dialog>`, CSS motion, no library (P0-09 step C)
Decision: Modal, SidePanel and BottomSheet share one engine (`Overlay.tsx`): a portalled `<dialog>` opened with `showModal()` (top layer; the page behind is inert to pointer and assistive tech), plus our own Tab wrap (`focus-trap.ts`), Esc on the dialog itself (top one only), a scroll-lock counter on `<html>` (`overflow: hidden`, scrollbar padded; no `position: fixed` body), focus back to the trigger (`overlay-trigger.ts` prefers the control clicked in the last second, because Safari does not focus buttons on click). Enter = `@starting-style`, exit = `[data-state="closing"]` whose transitions are awaited (`getAnimations()`), so reopening mid-exit reverses. Sheet drag: pointer events on handle + header, touch events on the content only while it is at its top; close rule is the pure `shouldCloseSheet` (25% or 0.5 px/ms over the last 100ms). New tokens `--scrim` and `--motion-on` (0 when motion is reduced: offsets vanish, overlays only fade).
Why: native inertness and top layer beat a hand-made `aria-hidden` sweep; CSS transitions are interruptible and run off the main thread; Motion is not installed until P0-10 and is not needed here (DESIGN §7 allows CSS for simple transitions). The sheet uses ease-out 220ms rather than the 380/32 spring.
Consequence / revisit when: P0-10 brings Motion: switch the sheet's spring-back to the token spring if it feels stiff on a real phone. Side panel leaves a 40px backdrop strip on phones so a tap beside it closes it.

## 2026-11-11 — Form controls: native inputs, hydration rule, outline contrast (P0-09 step B)
Decision: Select, Checkbox and Radio wrap native inputs (platform picker, arrow keys, form submit for free); the row is a `<label>` and the input is named by the label text only (`aria-labelledby`). Only *controlled* ones are disabled until hydrated (C-20): an uncontrolled native input keeps its state through hydration, so it stays usable without JS. Unchecked/unreached outlines use `--ink-3` (3.35:1), not `--line` (1.25:1), for WCAG 1.4.11. Avatar uses `next/image` with `unoptimized` (any origin, no optimiser config).
Why: AC8/AC13; accessibility over the softer look.
Consequence: a form that must work before hydration uses uncontrolled controls.

## 2026-11-11 — Touch-safe hover and 44px hit areas (P0-09 step A)
Decision: `globals.css` redefines Tailwind's `hover` variant as `@media (hover: hover) and (pointer: fine) { &:hover }`, so plain `hover:` classes are touch-safe; controls drawn under 44px get the `hit-44` utility (centred invisible `::after`, `max(100%, 44px)`). Controls whose target is bigger than what's drawn (Switch: the whole row) mark the visible part `data-press`, which scales on the parent's `:active` instead of the control itself.
Why: AC4/AC7; a transform on the Switch button would make it the containing block of its row-wide `::after` mid-press and lose clicks.
Consequence: `hit-44` elements must not use `overflow-hidden`; never reintroduce `[@media(hover:hover)]:` prefixes.

## 2026-11-11 — Toast announcers and Table row actions (P0-09 step A)
Decision: toasts are announced once, when they become visible, through two sr-only regions (`role=status` polite, `role=alert` for errors) cleared after 1 s; the visible list is a non-live `section` named "Notifications". Rows with an action get a real `<button data-row-action>` in the first cell named by `rowLabel`; the row's click handler runs the action once (ignores other controls and text selection).
Why: AC10 (no double reading, none dropped) and AC9 (keyboard rows without `tabindex` on `<tr>`).
Consequence: E2E must scope toast text to the "Notifications" region (it also appears in the announcer for 1 s).

## 2026-11-11 — P0-08: visual snapshots run on request, with per-OS baselines
Decision: `toHaveScreenshot` tests carry the tag `@visual` and are left out of ordinary runs and CI (`grepInvert` in `playwright.config.ts`). They run with `VISUAL=1`: `pnpm gate:phase` sets it, and `pnpm e2e:visual` runs only them (`--update-snapshots` accepts a new look). One browser (Chromium) holds the baselines, stored beside the spec with the OS in the file name (`…-chromium-win32.png`, `…-darwin.png`).
Why: font rendering differs between Windows, macOS and CI's Linux, so one shared baseline would fail on two of the three; TESTING §4 puts visual snapshots in the phase gate, which runs on a developer laptop.
Consequence: the first `VISUAL=1` run on a laptop without a baseline for its OS writes it and fails once: inspect the image, commit it. First baselines: token page at 390 and 1440 (Windows). The Mac baseline is created at the next phase gate run there.

## 2026-11-11 — P0-08: fonts, and what `display: swap` costs
Decision: Fraunces (variable, `opsz` axis kept) is the only preloaded font (67 KB); Manrope is not preloaded (DESIGN §12 budget). Both use `display: swap` with next/font's metric-adjusted fallback. AC 6 (CLS ≤ 0.01 at 320/390/1440) is asserted for a normal load and for fonts that never load. For fonts that arrive 1.5 s late the E2E bound is the Web Vitals "good" limit (≤ 0.1).
Why: measured on `/dev/ui` (Chromium, production build): normal load 0.000 at all three widths; fonts blocked 0.000; fonts 1.5 s late 0.000 at 320, 0.048 at 390 (one heading 6% wider in the fallback wraps to two lines, then returns to one), 0.009 at 1440 (one Manrope paragraph). A fallback can match average width, not every string, so a late swap can re-wrap a line that nearly fills its column. `display: optional` would remove the shift but show the fallback font for the whole visit on slow connections; tuning `size-adjust` to the gallery's sample strings would only move the mismatch to other text.
Consequence / revisit when: field CLS (P5 Lighthouse / real-user data) is above 0.05 on customer screens: then preload Manrope's Latin file or switch headings to `optional`.

## 2026-11-11 — P0-08: tokens page reads computed values; spacing unit; focus ring
Decision: (1) The `/dev/ui` token page and contrast table read values with `getComputedStyle`, so they show what the production CSS holds. The minifier rewrites values (`#ffffff` → `#fff`, `120ms` → `.12s`), so `parseHex` accepts 3- and 6-digit hex and the E2E compares values by meaning (hex expanded, durations in ms), not as strings. (2) Spacing utilities multiply one token, `--space-unit` (4px); the named steps (`--space-4` … ) exist for CSS that needs a fixed step. (3) The focus ring is an unlayered `:focus-visible` rule: `box-shadow` ink 2px + gold 4px, plus a transparent 2px outline that forced-colours mode paints.
Why: (1) found on the first production-build run: the contrast table showed "could not be read" because `--surface` arrived as `#fff`. (2) one source for the scale, no duplicated values (AC 3). (3) unlayered so it beats any component shadow in `@layer components`; `box-shadow` follows the element's radius and does not change its box (AC 4).
Consequence: a component that needs its own shadow while focused must add the two rings to it, not replace them. A colour token in another notation (`rgb()`, `oklch()`) makes the contrast table say so; extend `parseHex` then.

## 2026-11-10 — P0-08: display preferences, device and profile
Decision: `customer_profiles.sound_on` is now nullable with no default (migration 0013), like `reduce_motion`: null = no choice (sounds on, motion follows the system). The device keeps the choice in localStorage (`moz:motion`, `moz:sound`) plus a sync marker (`moz:prefs-sync`). Rule (`reconcile` in `src/lib/preferences.ts`): an unsent change on the device wins and is sent again; a device already in step follows the profile (also back to "no choice"); a choice made signed out is saved when the profile has none, otherwise the profile wins. Signed out or no customer profile → device-only, and the marker is cleared.
Why: AC 8 needs "the profile has none" to be detectable for sounds too; without the marker a second device could never return to "follow the system".
Consequence: the root layout reads the caller's preferences inside a Suspense boundary on full loads (one session + one profile query, only when a session cookie is present; anonymous requests cost nothing). Revisit if P1 adds a shared per-request session cache.

## 2026-11-10 — Found by the P0-13 walk-through: start-up grace and error-log throttle
Decision: (1) the scheduler-stale check waits until the monitoring worker has run 3 min (the snapshot carries `uptimeSec`): a fresh worker has no heartbeat yet, so every restart/deploy raised `health.scheduler`. (2) BullMQ `worker.error` lines are throttled per queue + message (first logged, repeats counted, `repeated: n` after 30 s; ≤ 200 keys): with Redis down they came several times a second per queue (232 lines in < 1 min), and the message was empty, so the error's code/name is logged instead.
Why: false alarms train people to ignore alerts; log spikes are a P0-13 edge case (rotation alone would just churn). Consequence: a scheduler that never starts is reported 3 min after the worker starts, not at once.

## 2026-11-10 — RLS policies: deny by default, the database re-checks roles (P0-20)
Decision: every table gets ENABLE + FORCE + per-role policies unless a migration declares it `-- rls: global <table> — <reason>` (now: feature_flags, content_settings, failed_jobs, job_heartbeats); the migration checker and a live-catalog test enforce it. Shop scope rows also need `app_in_shop()` (an active `shop_staff` row for user + shop) and admin scope `app_is_admin()` (active `admin_members`): SECURITY DEFINER PL/pgSQL owned by moz_auth, pinned search_path. Shops: public SELECT for every non-pending shop (PRODUCT §15). Own identity rows by `user_id = app_user_id()` under any scope. Session revocation trigger (0006) runs SECURITY DEFINER as moz_auth. Policies call every helper as `(SELECT f())`.
Why: a wrongly minted or stale scope gets nothing, not just a forgotten filter. Inlined `current_setting()` per row cost +65% p95; InitPlans fix that; a definer SQL function is re-planned per statement (0.08 ms) where PL/pgSQL caches (0.02 ms).

## 2026-11-10 — Outbox, relay, replay and payload versions (P0-18 C, on wip/P0-18)
Decision: side effects are `outbox` rows written in the change's transaction (`tools.outbox` in the action template; `writeOutbox` elsewhere; ids only, ≤ 8 KB, CHECK 16 KB backstop). Sweeper every minute: `opsAlert("outbox.stale")` for rows waiting > 2 min, prunes completed rows after 7 days. Payloads are `{ v, data }` with an upgrade chain per job; a newer version than the worker knows is moved to delayed for 30 s (DelayedError), never failed. First producer: the staff lockout email (audit row + outbox in one transaction).
Why: ARCHITECTURE §6, ENGINEERING §4–5, AC1/4/6/7. Polling, not LISTEN/NOTIFY: one VPS, ≤ 1 s latency is fine, and nothing extra to keep connected.
Security review (no BLOCK/HIGH) added: `failed_at` (dead-lettered rows leave replay and sweeps, pruned after 7 days like completed ones); the sweep re-dispatches rows dispatched > 10 min ago and still open (job lost from redis-queue) and raises `outbox.lost`; unknown job names are deferred for 1 h (rolling deploy) before dead-lettering; the claim is a `MATERIALIZED` CTE; boot refuses a queue/cache pair that is one server (`run_id`) or has the wrong eviction policies; limiter `onError` is required; after-commit follow-ups share one 2 s deadline; replay needs `--force` beyond 24 h and has `--dry-run`. Carried: C-29/C-30/C-12 → P0-20, C-31 → P0-13.
Consequence: delivery is at-least-once with completion de-duplication; a handler that crashes after its side effect but before `completed_at` can repeat on retry, so handlers stay idempotent. ## 2026-11-08 — Background jobs: BullMQ 6 design (P0-04)
> **Superseded (in part: side effects now go through the transactional outbox (P0-18); magic-link email is not queued).**
Decision: **bullmq 6.4.2 + ioredis 6.0.0**, pinned exactly. 6.4.2 is the newest release at least two weeks old; BullMQ shipped 6.5–6.7 this week, which is too fresh. The `msgpackr-extract` native build is not approved; BullMQ falls back to pure JS.

- Retries: 3 attempts, exponential backoff from 2 s. On the final attempt, or an `UnrecoverableError` such as a malformed payload, the processor wrapper writes `failed_jobs` (redacted payload and error) before BullMQ marks the job failed, so shutdown can't lose a dead letter.

- New jobs go into `JOBS` and `HANDLERS`, and handlers must be idempotent.
- Producers fail fast when Redis is down (no offline queue), so callers must handle the enqueue error.
- SIGTERM can't be delivered on Windows (Node terminates the process), so the signal path is unit-tested here and proven on the Linux staging deploy (P0-15).

## 2026-11-08 — Auth flows, MFA enforcement and session limits

## 2026-11-08 — Forms are uncontrolled until submit
