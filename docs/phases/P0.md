# P0 — Foundation and design system

**Goal:** a production-grade skeleton: secure auth for every role, an authorisation layer that makes cross-shop leaks structurally hard (app scopes **and** Row-Level Security), background jobs with a transactional outbox, CI with production-parity testing within the free GitHub budget, free-tier observability with internal SLOs, a hardened single VPS running staging (and, later, production) with encrypted backups and a tested restore, a complete design system with motion and sound foundations, and the three portal shells. Every later phase builds on this; shortcuts here multiply.

## How to work this phase
- Gates follow TESTING §4 exactly: `pnpm gate:task` per task (security-reviewer on security-relevant task diffs); light `/subphase-complete`; the one heavy `/phase-complete`. Until P0-14 builds the gate scripts and production-build E2E, run their steps by hand.
- **Order (plan v4): A → B → E → C → D.** Production foundations (CI, auth hardening, reliability, RLS, observability, staging) come before the design system and shells so that every later task is verified by CI and lands on staging. Inside P0-E: P0-14 → P0-19 → P0-18 → P0-20 → P0-13 → P0-21 → P0-15 → P0-16. P0-15 waits on human tasks (H-06, H-07, H-08, H-26, H-27); do the others meanwhile.
- **Retro rule:** P0-A and P0-B post-push checks are completed by P0-14 (CI green on their code) and P0-15 (staging smoke). P0-B closes when P0-14's CI is green.
- Before each task: the task's **Read** list only (plus ENGINEERING §1 once per session).
- A task is ticked only when every **Acceptance criterion** (and incoming CARRIED row) has evidence from this session (ENGINEERING §1); ≤ 5 evidence lines in SESSION_LOG.md, in the same commit.

### P0-06 · Authentication for all roles
**Depends on:** P0-03, P0-05.
**Read:** PRODUCT §2–3; SECURITY §2, §5; DESIGN §15 screen 2; reference `m02`/`d02`.
**Build:**
- Better Auth with Drizzle adapter (fall back to Auth.js only if a required capability is missing; log decision).
- Customers: Google OAuth (state + PKCE; scopes `openid email profile`; reject unverified emails) and email magic link (single-use, 15 min, hashed token storage). No passwords for customers.
- Staff/admin: email + password (Argon2id; min 12 chars; breached-password check via k-anonymity range API with timeout and fail-open-with-warning), mandatory TOTP enrolment before any dashboard access, 10 hashed single-use recovery codes, optional passkeys if the library supports them cleanly.
- Account linking rule: one user per verified email; Google and magic link resolve to the same user. Document in DECISIONS.md.
- Sessions: `__Host-` cookies, `Secure`, `HttpOnly`, `SameSite=Lax`; idle timeouts customer 30d / staff 12h / admin 2h; rotation on sign-in and privilege change; session list + "sign out everywhere".
- Return-URL allowlist (internal paths only, normalised); everything else falls back to the role's home.
- Throttling: magic-link requests and staff/admin logins per SECURITY §6; lockout notification email after repeated failures.
- UI: customer sign-in (screen 2: shop context when coming from a shop), "check your inbox", expired/used link page; staff/admin sign-in, TOTP enrolment (QR + manual key), TOTP challenge, recovery code entry. Magic-link email via React Email (rendered through Mailpit locally).
- Role context: users who are both customer and staff get an explicit switcher; default portal per role.
**Acceptance criteria:**
- Google and magic-link sign-in both work; reused or expired links show the friendly page.
- No staff/admin route reachable before TOTP is enrolled and verified (tested per route group).
- `?return=https://evil.com`, `//evil.com`, `/\evil.com` all fall back safely.
- Known vs unknown email for magic link: identical response body and status.
- Session timeouts enforced per role (tested with injected clock).
**Edge cases:** unverified Google email; email casing differences; user deleted mid-session; TOTP clock drift (±1 step); recovery code reuse.
**Tests:** integration for link lifecycle, TOTP gate, recovery codes, return-URL validation, throttling, timeouts; E2E customer magic-link sign-in via Mailpit API on Chromium + WebKit.
**Verify:** E2E summary; screenshots of sign-in (mobile + desktop).

**Build:** (DECISIONS "Pages slide as live content", 11 Nov: a snapshot can't be tapped mid-transition, so the page slide animates the live content and View Transitions only carry morphs) route transition wrapper `RouteTransition` (WAAPI enter on the live content, innermost changed one animates; `:root { view-transition-name: none }`, `::view-transition { pointer-events: none }`), directions `nav-forward` / `nav-back` / `nav-tab-forward` / `nav-tab-back` with a pure `navDirection(fromIndex, toIndex)` for tab order, a `TransitionLink` that records them (`setNavIntent`); shared-element naming helper `vtName(kind, id)` (CSS-safe, unique per entity) on React's `<ViewTransition share>`; the same enter where `document.startViewTransition` is missing (no morph), nothing on exit; sheet/modal enter/exit presets (the P0-09 overlay motion exposed as named presets, not re-implemented); popover scale-from-trigger (`transformOriginFor(trigger, popover)`); stagger helper (30–80ms, clamped); press/hover utilities documented (P0-09 `.pressable`, `[data-press]`, hover variant); reduced-motion variants (≤ 150ms fades). `/dev/motion` gallery (dev only, 404 in production) with demo pages for forward/back, tab order and card → detail.
**Acceptance criteria:**
1. Route transitions (Chromium and WebKit): forward navigation fades the new page in sliding 8px from the right (toward the left), back reverses it, tab switches slide only the tab content 6px in the direction of tab order (the bar holds still); from 1024px up the content cross-fades in place with no slide (DESIGN §7 "Desktop"), and a slide never makes the page wider than the screen; untyped navigations (browser back/forward) only fade; the page is never a view-transition snapshot (no `::view-transition-old/new(root)`); every animated property of the enter and of the morph's old/new snapshots is `transform` or `opacity`, each ≤ 380ms (`--dur-slow`), the morph groups' geometry is the browser's own (E2E reads `document.getAnimations()` during the transition).
2. Navigation never waits: during a running transition a click on the destination page's button registers (pointer events pass through); a second navigation started mid-transition ends on the second URL with no `::view-transition` animations left running and no console errors (E2E).
3. Shared element: in the card → detail demo the card image and title carry the same `vtName` as the detail header (the rest of the page only fades in while the morph runs) and the browser forms a pair (one element per name in each snapshot; E2E counts each name ≤ 1 in the DOM before and after); `vtName` is unit-tested (stable, CSS-safe for any id incl. leading digits and symbols, distinct kinds never collide).
4. Fallback: with `document.startViewTransition` removed before load and with VT present but transition types unsupported (downgraded by the head script), in Chromium and WebKit, navigation works, the new page enters with the same fade + 8px slide ≤ 380ms (transform/opacity only), nothing animates on exit, no morph runs, and there are no console errors.
5. Reduced motion (system setting or `data-reduce-motion="true"`): nothing on `/dev/motion` moves; route transitions, presets, popover and stagger become opacity fades ≤ 150ms or no animation (E2E reads computed keyframes/transitions; no `translate`/`scale` values).
6. Primitives animate only `transform` and `opacity`: a unit test reads the motion CSS (keyframes + transition properties of the presets and route-transition rules) and fails on any other property; durations come from tokens (existing hex/duration lint).
7. Stagger: `staggerDelay(index)` returns 30–80ms steps (clamped: items after the 8th share the last delay so a long list never takes more than ~0.6s); staggered items are in the DOM, readable by assistive tech and clickable from first paint (no `pointer-events: none`, no `visibility: hidden`) (unit + E2E click on the last item immediately).
